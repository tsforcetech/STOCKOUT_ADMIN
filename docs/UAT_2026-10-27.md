## 2. What was built

### Buyer site and seller portal (`stockout_buyer`)
- **Sign-out (B3):** now calls `POST /auth/logout {refreshToken}` first, then falls back to `DELETE /auth/sessions/{sid}`. The browser session is always cleared. If the server confirmed neither call, the user is told the session couldn't be ended on the server, instead of being told they're signed out everywhere.
- **Buyer eligibility (BK-1):** the cart shows the result of `GET /marketplace/buyer/eligibility`.
  - Eligible: "can buy, no company verification needed".
  - Suspended, locked, disabled, pending, not found or unavailable: an explanation, and buying is never treated as allowed.
  - Checkout stays "coming soon", shown separately from eligibility.
  - No buyer KYC screens exist.
- **Company team** (`/seller/team`, permission-gated through `my-permissions`):
  - Members list with role, status and joined date.
  - Change role, suspend or reactivate, remove, and make owner (`transfer-ownership` with `newOwnerMemberId`).
  - The last active owner is protected, and rows without a valid `memberId` are disabled.
  - Invitations: invite (Admin/Manager/Staff), list, resend and cancel.
- **Invitation landing** (`/invitations/:token`):
  - Public preview with masked email, role, expiry and status.
  - Accepting asks visitors to sign in first; then calls `accept` and reloads the seller contexts.
  - Expired, used or invalid links are handled.
  - The token is only ever sent in the request path.
- **Business changes** (`/seller/business-changes`):
  - List and create a draft. Fields per category use the exact keys the approval procedure applies, e.g. `bankIban` and `tradeLicenseExpiresAtUtc`.
  - Attach evidence (upload as `SELLER_DOCUMENT`, then link `mediaAssetId`) and submit.
  - Deadline and overdue status are shown **as returned by the server** in GST; nothing is calculated in the browser.
  - `UAE_CALENDAR_COVERAGE_MISSING` is shown in plain words.
- **Remove profile photo (C6):** sends `profileImageAssetId: null` and only reports success when the returned profile has no photo.

### Admin console (`stockout_admin`)
- **Sign-out:** same server-first logout as the buyer site.
- **Remove profile photo:** same as the buyer site.
- **Business changes** (`/business-changes`, `organizations.business_changes.view`):
  - Paged queue with filters for status, change type and overdue-only; deadlines shown in GST.
  - Detail view: current vs proposed values, evidence list and history.
  - Approve with optional notes; reject with a required reason. Each action is shown only with its permission.
  - KYC re-verification warning for sensitive categories.
- **UAE calendar** (`/calendar`, `organizations.calendar.view`):
  - Configuration view, plus an edit dialog (weekend days, approved-through year, active flag, required reason) with `calendar.manage`.
  - Holidays per year.
  - "Confirm" for provisional holidays with `calendar.holidays.confirm`. Requires authority, title, reference, a publication date not in the future, verification remarks and attestation. Placeholder URLs are rejected. No dates are hard-coded.

### Kept as is (already done 26 Oct)
- PA-1A policies, cookie and communication preferences.
- Seller KYC: business-only onboarding, profile, four-category checklist, two-part signatory, VAT types, `canList` notice.
- Admin per-document review, seller history and policy admin.
- The identity fallback stays until `/identity/me` returns 200 live.

### Not built (no backend yet)
- Checkout, orders, payments, RFQ (E4/D).
- Inspector listing edits (E5/L22).
- Reviewer download for business-change evidence: the API has no download URL for those files yet.

## 3. Guide vs code: what the frontend follows (source wins)

| PA-1B.2 guide says | Controller / DTO says (used) |
|---|---|
| `GET /organizations/my-memberships` | `GET /organizations/me/memberships`; response is `OrganizationMembershipSummary` (`membership`, `buyerCapability`, `sellerCapability`, `permissions`) |
| `PUT …/members/{userId}/status` | `POST …/members/{memberId}/suspend`, `POST …/reactivate`, `DELETE …/members/{memberId}?expectedRowVersion=` |
| `POST …/ownership-transfer {targetUserId, reason}` | `POST …/transfer-ownership {newOwnerMemberId, expectedRowVersion}` |
| Business change `{changeReason, effectiveDateUtc, proposedValuesJson}` | `{changeCategory, reason, effectiveDate, proposedValues (object), documents?}` |
| Document `{fileAssetId, documentType, documentName}` | `{documentType, mediaAssetId, fileName, fileSize, mimeType}` |
| Invitation response `invitationStatus` | `status`, plus `invitedByUserId`, `resentCount`, `lastResentAtUtc`, `rowVersion` |
| Preview `organizationLegalName`, `roleName`, `isExpired` | `organizationName`, `roleCode`, `status`, `expiresAtUtc`, `maskedEmail` |
| Admin queue: array | Paged object (live) |
| Holiday confirm `sourceReference` field | Not in `ConfirmPublicHolidayRequest`, so it isn't sent |
